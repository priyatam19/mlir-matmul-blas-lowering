# Custom Matmul Tiling Extension

This extension adds a custom MLIR pass to the tutorial pipeline:

```bash
--tile-matmul-for-cache="tile-m=2 tile-n=4 tile-k=4"
```

The pass runs on tensor-level `linalg.matmul` operations emitted by
torch-mlir and rewrites them into tiled `scf.for` nests around smaller
`linalg.matmul` operations. The CPU path can then bufferize and lower tiled
matmuls to OpenBLAS calls. The GPU path maps the tiled loops through GPU
dialect and NVPTX code generation.

## CPU/OpenBLAS Demo

```bash
cd /workspace/project/src/sample
python3 lower_sample_model.py
bash run_tiled_mlir_pipeline.sh
./tiled.out
```

Artifacts:

- `sample_model_linalg.mlir`: torch-mlir output from the PyTorch `Sample`
  module.
- `sample_model_tiled_buf_linalg.mlir`: contains the custom tiled `scf.for`
  matmul structure.
- `sample_model_tiled_llvm_ir.ll`: LLVM IR for the native executable.
- `tiled.out`: CPU executable linked with OpenBLAS.

## CUDA/NVPTX Codegen Demo

```bash
cd /workspace/project/src/sample/gpu
cp ../sample_model_linalg.mlir .
bash run_gpu_dialect_pipeline.sh
bash run_mlir_pipeline.sh
```

Artifacts:

- `sample_gpu_dialect.mlir`: outlined `gpu.module` kernels after mapping
  tiled linalg loops to the GPU dialect.
- `sample_nvptx_isa.mlir`: embedded PTX ISA generated by LLVM's NVPTX
  backend for `sm_90`.
- `sample.ll` and `sample.o`: host-side LLVM IR and object file.

The current Docker image and host can generate NVPTX/PTX code, but they do not
include an NVIDIA GPU, CUDA driver/runtime libraries, or the MLIR CUDA runtime
library needed to link and launch a GPU executable locally.
